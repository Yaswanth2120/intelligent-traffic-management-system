# kind deployment evidence — 2026-08-16

Environment: MacBook Air M2, Docker Desktop 29.4.1, kind 0.32.0, Kubernetes
v1.36.1. This is a local cluster, not a public deployment.

`kubectl -n traffic-platform get pods` showed Ready application and support
pods: gateway, feature service, decision engine, ML service, Kafka, Redis,
Postgres, Prometheus, and Grafana.

Health checks succeeded from in-cluster curl pods:

```text
GET gateway-service:8080/actuator/health -> {"status":"UP","groups":["liveness","readiness"]}
GET ml-service:8000/health -> 200
GET grafana:3000/api/health -> 200
```

Flow validation sent 20 requests to `gateway-service:8080/api/orders`; the
Postgres query `select count(*) from traffic_history` returned `36`, proving
feature-service persisted pipeline traffic. Prometheus query `up` returned
`1` for gateway-service, feature-service, decision-engine, and ml-service.

CPU HPA validation used only Metrics Server resource data. A temporary CPU
loop in the gateway pod produced:

```text
gateway-service HPA: cpu 249% / target 65%, replicas 3
kubectl top: three gateway pods at approximately 499-500m CPU
```

The HPA then requested four gateway replicas; after the load was removed all
four replacement pods were Ready. No custom/external metrics were configured.

The pinned ingress-nginx controller was also Ready and the
`traffic-platform.local` Ingress resource was accepted. The kind profile does
not claim a public DNS name; use the documented port-forwards for local access.
